เทสต์ของคน A (หน้าร้าน, บัญชีลูกค้า, ตะกร้า, จัดสเปค, เคลม, ลูกค้าในหลังร้าน, ผู้ใช้, Login)

ระบบแจ้งซ่อมภายใน (แจ้งปัญหา, คำร้องของฉัน, ศูนย์มอบหมายงาน, งานที่ได้รับมอบหมาย) ปิดแล้ว งานบริการหลังการขายย้ายไปอยู่ในระบบเคลม — เทสต์งานช่างอยู่ที่ `e2e/b/claim-service.spec.ts`

ไฟล์ที่ลงท้าย `.mobile.spec.ts` จะรันบนจอขนาดมือถือ (Pixel 7) 

| ไฟล์ | ครอบคลุม |
|---|---|
| `access.spec.ts` | สิทธิ์เปิดเมนูของแต่ละบทบาท, ยังไม่ล็อกอินถูกพาไปหน้า Login, รหัสผิด, หน้าแจ้งซ่อมเดิมเป็น 404, บัญชีพนักงานทั่วไปถูกระงับ |
| `users.spec.ts` | Admin สร้างบัญชี (รหัส ≥ 8 ตัว, username ซ้ำไม่ได้), ถอดสิทธิ์ตัวเองไม่ได้, ระงับบัญชีแล้วหลุดทันที |
| `login-next.spec.ts` | หลังล็อกอินกลับไปหน้าที่เปิดไว้ (รวม query เช่น `/purchase?page=2`), หน้าที่ไม่มีสิทธิ์ → หน้าแรกของตัวเอง, ไม่พาไปเว็บอื่น (`//…`, `https://…`, `javascript:`) |
| `password.spec.ts` | เปลี่ยนรหัสผ่านเอง: ตรวจความถูกต้อง, อุปกรณ์อื่นถูกออกจากระบบ |
| `forgot-password.spec.ts` | ลืมรหัสผ่าน: ตอบเหมือนกันทุกกรณี, จำกัด 3 ครั้ง/ชม., ลิงก์ใช้ครั้งเดียว/หมดอายุ |
| `asset-scan.mobile.spec.ts`, `asset-scan-camera.mobile.spec.ts` | ปุ่มสแกน Serial ในหน้าตรวจประกัน (ตัวเดียวกับตอนแพ็กของ): อ่าน QR จากกล้อง (กล้องจำลองด้วยวิดีโอ), ไม่มีกล้อง→อ่านจากรูปถ่าย Code 128, รูปที่ไม่มีบาร์โค้ด, ยกเลิก, ไฟล์ WASM เสิร์ฟจากแอปเอง |
| `storefront.spec.ts` | หน้าร้าน: หน้าแรก (หมวด/สินค้า), ค้นหาทุกคำ, สินค้าที่ปิดไว้ไม่แสดง/404, กรองหมวด+ยี่ห้อ, เรียงราคา, มีสินค้าเท่านั้น, หน้าสินค้า (ราคา/ส่วนลด/คงเหลือ/ประกัน/สเปค) |
| `storefront.mobile.spec.ts` | หน้าร้านบนมือถือ: ไม่ล้นจอ, ตัวกรองเลื่อนแนวนอน, 2 การ์ดต่อแถว, ช่องค้นหา 16px |
| `customer-auth.spec.ts` | ลูกค้า: สมัคร (ตรวจอีเมล/รหัส ≥ 8/ยืนยันรหัส/เบอร์/ซ้ำ, เก็บ hash), เข้า/ออกจากระบบ, หน้าบัญชี, บัญชีถูกระงับ, กลับไป /checkout หลัง login, ไม่พาไปเว็บอื่น, session ลูกค้าเข้าหลังร้านไม่ได้ |
| `cart.spec.ts` | ตะกร้า: ผู้เยี่ยมชมมีตะกร้าเอง (cookie + เก็บแค่ hash), จำกัดตามสต็อก, เพิ่ม/ลด/ลบ, ใกล้ส่งฟรี, login แล้วรวมเข้าตะกร้าลูกค้า (จำกัดตามสต็อก) ไปต่อ /checkout, รายการที่ขายไม่ได้แล้วกันการสั่งซื้อ |
| `my-orders.spec.ts` | คำสั่งซื้อของฉัน: เห็นเฉพาะของตัวเอง ใหม่สุดก่อน, ปุ่มถัดไปตามสถานะ (ชำระเงิน / ติดตามพัสดุ / ดูรายละเอียด), รอชำระที่เลยเวลาแสดงหมดเวลา, แท็บสถานะพร้อมจำนวน, หน้าบัญชีแสดง 3 รายการล่าสุด, ลิงก์ /pay ตอนยังไม่ login กลับมาหลังเข้าสู่ระบบ |
| `customers-admin.spec.ts` | หลังร้าน › ลูกค้า: รายชื่อ/ค้นหา/แท็บสถานะ, หน้าลูกค้า (ติดต่อ ที่อยู่ คำสั่งซื้อ), ระงับบัญชี→ออกจากระบบทุกอุปกรณ์ + Audit Log, เปิดใช้ใหม่, id ไม่มี→404 (สิทธิ์ดูใน `access.spec.ts`) |
| `chat.spec.ts` | แชทสดหน้าร้าน: ผู้เยี่ยมชมต้องบอกชื่อก่อน, พนักงานเห็นในคิวรอรับเรื่อง + จำนวนยังไม่อ่าน, ตอบแล้วรับเรื่อง, ข้อความขึ้นทั้งสองฝั่งโดยไม่รีโหลด, ปิดแชท + Audit, เริ่มบทสนทนาใหม่, ลูกค้าไม่อยู่ → อีเมล 1 ฉบับต่อช่วง พร้อมลิงก์ `?chat=1`, สมาชิกไม่ต้องกรอกชื่อ + พนักงานเห็นคำสั่งซื้อ, ลูกค้าจบแชทเอง, สิทธิ์อ่านแชท |
| `compat.spec.ts` | กฎความเข้ากันจัดสเปค (`src/lib/compat.ts`, ไม่เปิดเบราว์เซอร์): Socket, ชนิดแรม, SODIMM, ขนาดบอร์ด↔เคส, ความยาวการ์ดจอ, กราฟิกในตัว, ชุดระบายความร้อน, M.2, กำลังไฟ, ไม่มีข้อมูลสเปค |
| `pc-builder.spec.ts` | หน้าจัดสเปค: เลือกครบชุด AM5, ตัวที่ใช้ไม่ได้บอกเหตุผลและกดเลือกไม่ได้, ราคารวม/ประเมินไฟ, ใส่ตะกร้าทั้งชุด, ชุดที่ไม่เข้ากันกดใส่ตะกร้าไม่ได้, SKU ผิดถูกตัดทิ้ง, บันทึก/เปิด/ลบสเปคในบัญชี |
| `claims.spec.ts` | เคลมสินค้า: ลูกค้าเลือกเครื่องจากคำสั่งซื้อของตัวเอง (ตรวจอาการ ≥ 10 ตัว, เคลมซ้ำไม่ได้, หมดประกันไม่ได้), ร้านรับเครื่อง → เปลี่ยนเครื่องผ่าน `replaceUnit` (สต็อก/Serial/Audit ถูกต้อง, Serial ผิดถูกปฏิเสธ), ลูกค้ายกเลิก, ไม่อนุมัติพร้อมเหตุผล, อีเมลทุกขั้น, สิทธิ์เข้าหน้า |

กติกาในโฟลเดอร์นี้: ไม่แก้บัญชีตัวอย่าง (รหัส `1234` ต้องใช้ได้เสมอ เพราะเทสต์ของคน B ใช้) — สร้างบัญชี/ข้อมูลทดสอบที่ขึ้นต้นด้วย `e2e-` / `E2E` เอง แล้วลบใน `afterAll` (`util.ts` มีตัวช่วย `as()`, `makeUser()`, `dropUsers()`)
